# 报告图片如何用于课程网站

仓库地址：https://github.com/70clementine/Bert-Lab

项目中的 `新实验报告.md` 使用相对图片路径，适合在本机和 GitHub 中阅读，例如：

```markdown
![三轮训练验证曲线与测试集结果](artifacts/report/quality.png)
```

如果只上传或粘贴 Markdown 报告，课程网站没有这些本地图片，应改成可访问的图片文件 URL。支持 Markdown 外链图片时，三处图片可分别写为：

```markdown
![三轮训练验证曲线与测试集结果](https://raw.githubusercontent.com/70clementine/Bert-Lab/main/artifacts/report/quality.png)

![新闻与古文的行归一化混淆矩阵](https://raw.githubusercontent.com/70clementine/Bert-Lab/main/artifacts/v2/confusion.png)

![batch 大小与端到端吞吐](https://raw.githubusercontent.com/70clementine/Bert-Lab/main/artifacts/v2/speed.png)
```

这里是图片文件本身的地址，不是 GitHub 的 `blob/main/...` 文件浏览页面。为固定提交时的图，可以把 URL 中的 `main` 替换为对应提交的完整 commit SHA，避免后续更新覆盖图像内容。

如果课程网站屏蔽外链图片，或学校网络不能访问该域名，最稳妥的方式是使用网站的“上传图片/插入图片”功能上传这三张 PNG，再把括号内地址替换成网站返回的图片 URL。例如：

```markdown
![训练与验证结果](课程网站上传后返回的图片URL)
```

若网站提供富文本编辑器，通常应直接插入图片，而不是粘贴 Markdown 语法。若网站支持连同附件目录一起上传并解析相对路径，可以保持 `artifacts/` 的目录结构，无需修改相对引用。具体能力取决于课程网站。

提交前应在网站最终预览中检查三张图；不要使用 `E:\...` 本机路径。私有仓库的图片不能作为其他人无需登录即可访问的公开图床，也不要把访问令牌写进图片链接。

格式依据：[GitHub 官方图片及相对链接说明](https://docs.github.com/en/get-started/writing-on-github/getting-started-with-writing-and-formatting-on-github/basic-writing-and-formatting-syntax#images)。
